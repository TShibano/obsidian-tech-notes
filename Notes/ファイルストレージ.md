## 概要

ファイルストレージは，データをファイルとして階層的なディレクトリ構造で管理するストレージ方式．NFS や SMB/CIFS プロトコルを通じてネットワーク経由で複数サーバからアクセスでき，共有ファイルサーバ（[[NAS]]）として広く使われる．

## 詳細

### 3種のストレージ方式の比較

| 比較項目 | ファイルストレージ | [[ブロックストレージ]] | [[オブジェクトストレージ]] |
|---------|-----------------|------------------|---------------------|
| データ単位 | ファイル | 固定サイズのブロック | オブジェクト（データ＋メタデータ） |
| 構造 | 階層型ディレクトリ | フラット（アドレス指定） | フラット（URL/キー指定） |
| アクセス方法 | NFS, SMB/CIFS | iSCSI, FC | HTTP/REST |
| パフォーマンス | 中程度 | 高い（低レイテンシ） | 低め（高スループット） |
| スケーラビリティ | 中程度 | 中程度 | 非常に高い（ペタバイト超） |
| 主な用途 | 共有ファイルサーバ，開発環境 | DB，OS ボリューム | バックアップ，メディア，ビッグデータ |

### ファイルストレージの仕組み

1. **メタデータ管理**: ファイル名，パーミッション，タイムスタンプ等をメタデータとして管理
2. **ディレクトリツリー**: パス（`/home/user/file.txt`）でファイルを一意に特定
3. **ロック機構**: 複数クライアントの同時アクセスを制御

### NAS（Network Attached Storage）

ネットワークに接続されたファイルストレージ専用アプライアンス．NFSやCIFSプロトコルを提供し，複数のサーバから同時マウントが可能．[[SAN(ストレージエリアネットワーク)|SAN]] とは異なり，ファイルシステムレベルでの共有を行う．

### クラウドにおけるファイルストレージ

- **AWS EFS**（Elastic File System）: NFS v4 互換，マルチAZ
- **Azure Files**: SMB/NFS，Active Directory 統合
- **Google Cloud Filestore**: NFS，GKE との統合

## ポイント

- アクセス頻度が高く共有が必要なデータ（コンテンツ，設定ファイル等）に適する
- [[ブロックストレージ]] に比べてオーバーヘッドがあるため，DB用途には向かない
- クラウドネイティブ環境では [[オブジェクトストレージ]] に移行するケースも多い
